# CH-1 job activation terms v1

Migration 0109 and the existing practice activation endpoint implement the synthetic v3 path. Real PostgreSQL/browser verification and independent acceptance remain required.

`switch-live.v3` is a strict server-internal command binding activation and terms IDs to a job, the accepted document ID/version/hash and the expected job revision. It accepts no tenant, net value, small-job flag, policy, commercial track or trial/plan context supplied by a client. Authorization and tenant membership remain responsibilities of the existing command boundary.

`job-activation-terms.v1` records tenant/job, activation, baseline quote identity and document version/hash, accepted net pence, highest sent net pence, small-job flag, policy, commercial track, trial/plan context and activation time. All amounts are nonnegative integer GBP pence within the application's 1,000,000,000,000-pence bound. A missing sent quote is represented by a highest sent net of zero. A sent quote means an immutable document revision with an outbound send record; status alone is insufficient.

Small-job classification is `max(acceptedNetPence, highestSentNetPence) < 200000`. The terms schema checks that the stored boolean agrees with those values. SV-1's exported success-fee schema supplies the v3 fee-policy identity; this contract does not define a second policy. Only the small-builder track is supported here.

Trial/plan context is the closed, non-null literal `none_recorded_pre_mon2a`, per the coordinator ruling of 8 October 2026, INDEX.md “Coordinator rulings, round 3”, supplied in the issued CH-1 header. MON-2A/MON-3 own its future replacement. This value is not a trial or plan entitlement.

Migration `0109_job_activation_terms.sql` adds the immutable tenant-owned terms table and a narrowly authorized v3 routine. It preserves the historic routine and records no historic financial effects for v3 jobs. Runtime SELECT/INSERT grants are paired with a controlled-insert trigger; UPDATE/DELETE/TRUNCATE are denied. The routine binds the accepted quote identity/version/hash, derives amounts from persisted commercial revisions, validates the owner membership and approved exact authorization, and retains SH-1/CH-3a triggers. The mutation’s lock hook makes the dispatcher recheck active owner membership even on receipt replay, then locks the job before receipt allocation; the routine reuses that lock. The dispatcher appends audit events in the same transaction after all business locks.

`GET/POST /api/jobs/:id/quotes/activation` remains the shared web/Nest boundary, authenticated by PracticeAccess before any read or replay. Its additive response includes `terms`, `savedV1Sample` and `effects.termsRows`; the existing response version remains 1. Client small flags, policy, track, terms and deployment mode are refused by the strict command schema. New jobs accept only the no-charge scenario. The existing CH-2-classified `job.switch_live` command type is reused with the strict v3 payload and a distinct `practice-start-v3` semantic key; no new route or registry entry is added. The scenario participates in the command hash, including on replay; a changed payload under the same ID conflicts.

For the five authorized regression specs, session issuance saves a generated v1 proposal owned by that session (`practice_scenario='v1_sample'`). The immutable server-only `saved_v1_sample` marker selects the historic practice facade. It creates neither an activation nor an obligation until that sample is explicitly started. Existing v1 activations keep their original records and facade. Historic UI appears inside open disclosure sections labelled “Earlier proposed pricing (v1)”, preserving the unchanged checks. The new shared test helper opens this saved job and performs the same scope review steps; it creates no fresh capture and intercepts no API.

`seedActivationFixturesV3` prepares the three named fictional accepted quotes with £1,000.00, £18,800.00 and £30,000.00 nets, using the real quote/send/acceptance commands, then the real v3 command through runtime credentials. The owner pool is only for source/party setup. It requires synthetic mode and the fixed synthetic tenant. DEMO-S retains the full shadow journey. MON-1’s future trip is not implemented here.
