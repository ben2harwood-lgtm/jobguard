# M4-12-S: fake-rail collection and refund

Only synthetic small-builder jobs owned by a current practice session can use this boundary. No provider SDK, webhook, network action or real money is involved. The explicit reconciliation buttons are an in-process fake rail: they append simulated facts, never accept provider authority.

`simulation-fee-collection-command.v1` uses a UUID command identity. `collect` and `refund` bind the current immutable numbered statement ID/hash and the exact GBP principal displayed by the approval button. The database derives available principal under the same source fences and tenant statement lock as migration 0490; a stale amount fails instead of authorizing a different amount. It reuses the existing statement approval routine, then records a separate approved Decision and authorization bound to the attempt, fake recipient, statement hash, amount, policy and session expiry. Pending reservation, event, receipt and audit commit together.

Attempt and event tables are immutable, FORCE RLS and owner-only; runtime has only two session-checked entrypoints. Collection reserves outstanding principal minus active collection reservations. Refund reserves excess settled principal above current source-backed entitlement minus active refund reservations. Collection and refund reservations cannot overlap. An unknown outcome fences every new attempt until explicit fake reconciliation. Unknown reservations never expire automatically.

`redirect`, `unknown`, `settle` and `fail` identify an existing attempt in this job. Redirect preserves its state. Pending and unknown attempts can reconcile to settled or definite failure; terminal outcomes cannot change. Duplicate commands return their saved result after fresh access checks; a changed payload, job or actor conflicts. New command IDs for an already recorded terminal outcome add no settlement event. Definitive failure releases reserved capacity; unknown retains it.

The projection sums each attempt's latest immutable event. Collection settlements, refunds and retained principal remain distinct. A corrected statement never rewrites the original or its hash. A reversal can therefore show refund due before the fake refund settles. The canonical browser transport fixture shows £282 collected, £250 refund due/refunded and £32 retained. PostgreSQL integration tests independently exercise general bounds with genuine £80 source-backed fixture principal; transport mocks are not database proof.

Migration 0491 is additive. Forward fix only: preserve attempts, unknown outcomes, events and approvals. Do not roll back by removing financial history. No subscription routine (including latest `app.mon2_issue` from 0374) is replaced or modified. Real providers, real-data operation, policy approval and independent RED review remain separate gates.
