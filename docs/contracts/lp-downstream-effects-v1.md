**Status: PROPOSED — needs review.** Companion to [the design note](lp-command-binding-design-v1.md). No grants, scanner pins, LP-0 baseline or migrations are changed. This appendix is design input, not accepted catalogue evidence.

Base: `cc147d78` (LP-DESIGN-NOTE-FIX checkout) (inspected 29 October 2026). Sources: the 144 migration SQL files through migration `0347`, and the LP-0 JSON entries, recorded routines, RLS and trigger records from the inventory’s recorded input [`lp-downstream-lp-0-recorded-input-v1.json`](lp-downstream-lp-0-recorded-input-v1.json) (copied from `lp-0-effective-privileges-v1.json` on main `baad7d56`, 29 October 2026). The live LP-0 JSON is excluded. The migration boundary is recorded as `MAX_MIGRATION` in `tools/lp-downstream-inventory.py`; newer migrations are excluded. To refresh this design snapshot, update the recorded LP-0 input and migration boundary as needed, and regenerate this document together. All source references below are repository-relative.

This is a conservative **superset** of reachable objects: source declarations include historical/replaced/dropped objects; LP-0 reachability is its recorded observation, not a fresh measurement. Routine rows group names and retain every LP-0 overload in the final column. Source-only names require an overload/catalogue check. No row means “safe working data”. Regenerate with `python3 tools/lp-downstream-inventory.py`; use `--check` to detect drift. Family assignments prefer LP-0 group domain kinds and schema declarations (money columns, hidden result fields and the ENT-6B billing schema), then combine name hints and direct-write target effects. Classes overlap: queue work can also be hidden. These remain navigation hints; each is a downstream-effect **hypothesis**, not a policy or proof. Transitive consequences are explained in the companion path table and must be followed through the listed call/trigger edges. Each later card must resolve the applicable subset, trace actual callers, trigger edges, views, dynamic SQL and all overloads as the real role, then pair refusal with an allowed case and committed-state checks. The full LP-0 guard remains authoritative for its frozen capabilities. Do not regenerate its expected facts from this appendix.

Cards in the object index combine the existing LP-0 group assignments with the proposed primary/direct-write classes above. A shared assignment splits responsibilities by the card contracts in §11.8: binding (LP-6), checked write closure (LP-5/8), worker separation (LP-10), policy visibility (LP-11), owner narrowing (LP-12), bounded legacy items (LP-13), and final refusal proof (LP-9). LP-13 never absorbs an earlier authority/money fix. Pure extensions and trigger-only functions remain listed because helper or trigger composition may be reachable.
