# Extra evidence pack writer v1 — ENT-5 partial slice

ENT-5-PACK-WRITER is RED. It adds an internal repository adapter and migration 0672; ENT-5 is still not complete. It builds on ENT-5-PACK-TIMING, now on main via #624 and merged into this branch by the launcher. Existing contracts are unchanged.

Decision: Only a contractor surveyor or commercial manager whose current grant covers the job may create a pack, through one new database routine called inside the existing authenticated withTenant boundary, with a command receipt (existing command_receipt pattern; exact replay of the same command returns the same pack, a different payload under the same command id is a typed conflict).

`ExtraEvidencePackWriter.create(context, input)` accepts strict `create-extra-evidence-pack.v1`: command ID, job ID, extra ID and expected manifest digest. It accepts no actor ID, tenant override or artifact content. Both `JOBGUARD_ENV=synthetic_demo` and the database's existing `jobguard_synthetic_demo` guard are required. The SQL routine requires the sealed request's current actor and tenant, an active surveyor/commercial-manager grant covering the job, and a command-origin contractor extra in that exact job. An unbound queued context cannot write. Current authority is checked on exact replay too.

The server loads persisted sources, commits, and assembles through the existing adapter, including exact private object versions and verified hashes. Storage I/O holds no business locks. It rejects a supplied digest differing from this fresh assembly. Before insertion a second authenticated transaction acquires the existing tenant authority/job locks, reloads sources and refuses any difference from the prepared snapshot (`EXTRA_PACK_SOURCE_CHANGED`). A caller retries that failure with a freshly assembled digest. Source failures retain the source adapter's typed failures. Optional absent material remains an explicit omission; required missing, pending, invalidated or invalid sources refuse. No client artifact is ever forwarded to the writer.

`app.store_extra_pack_artifact` is the single internal SQL writer. A NULL artifact probes exact replay without reserving an incomplete receipt. A new write atomically inserts a succeeded `CreateExtraEvidencePack` receipt, the existing immutable subject container and `app.extra_pack_artifact`, then seals a checked-operation audit event as its final lock. The routine validates the subject envelope, manifest digest, held omissions, source-entry correspondence and source content hashes. The trusted server adapter supplies the persisted-source reassembly and original-byte validation; SQL does not perform storage I/O or independently authenticate photographic assertions. As with the existing tenant context boundary, this is not protection against a compromised application/database credential.

The new table stores content version, manifest digest, full source pack and its source references, tenant/job/extra/pack identity, command, actor membership and server time. Runtime has SELECT only and narrow routine EXECUTE; RLS is forced. UPDATE and DELETE triggers reject even owner attempts, while runtime also lacks DML/TRUNCATE grants. The routine may inspect the existing sealed request binding via narrowly granted current-actor/current-tenant access for its trusted migration owner. No change to binding semantics or session authentication is made.

Exact command replay returns the same pack without reassembling newer history. A changed digest, subject or actor under the same command ID is `EXTRA_PACK_COMMAND_CONFLICT`. A new command after a later approval creates a new snapshot; the previous artifact and omissions remain unchanged. The merged `verifyExtraSourcePack` / `inspectExtraSourcePack` verifier consumes the stored artifact. A persisted digest is an integrity anchor within this trust boundary, not an independent external checkpoint. Altered/missing sources are detected; genuine held omissions still produce missing-source findings.

Every artifact retains `completeApprovalPack=false`, `Client access HELD` and `Export and send HELD`. There is no HTTP route, download, client access, export/send, provider, fee, release or completeness claim. This slice does not close any other ENT-5 acceptance assertion.

Forward fix: additive reviewed migration; preserve snapshots and receipts. There is no destructive rollback or backfill. Older application code ignores the new table.
