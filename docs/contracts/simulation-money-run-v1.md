# M4-17-S persisted simulation reconciliation

`simulation-money-command.v1` is a strict boundary: `run` accepts only a command UUID; `read`, `review` and `restore` also bind the saved run UUID and source hash. No caller supplies amounts, snapshots, settlements or a completed report. The workspace endpoint is POST `/api/jobs/:id/success-fees/money-check`, behind the existing synthetic owner/session/job boundary. No provider or scheduled worker is introduced.

Migration 0492 adds two private immutable tenant tables and two routines. Only the run routine is executable by runtime; the source loader is private. Source rows are gathered under a synthetic coarse table fence before the audit head is acquired. All reads and replays reauthenticate. Before final lock, the routine refuses before any protected-source read. Subscription rows are tenant-level; customer and fee rows are job-level, with separately labelled books.

A run stores the server snapshot and canonical SHA-256. The deterministic report is reproduced from that snapshot, with its own hash. It retains source references and flags missing sources, orphan/duplicate/late/unknown events, over-allocation, broken invoice bindings, journal imbalance, collection/posting disagreement, and subscription period/statement/settlement disagreement. It never clamps a negative balance, changes authoritative books, deletes history or fabricates settlement. An empty subscription book has zero periods and zero principal; it is not represented as a paid subscription.

Review acknowledges these exact current source rows. It does not clear differences or execute an adjustment. Corrections still need the original domain command and approval. A stale checkpoint can be read as history, but cannot be reviewed or restored as current. Restore verifies the current source hash and persists a new run containing the same snapshot; it always reports execution paused and has no execution/resume operation. This is a reconciliation-checkpoint restore, not a PostgreSQL backup/restore or an application-wide payment kill switch.

The `recovery-18800` end state is not implemented by inventing rows: this base's 0392 derivations require `delta_pence >= 0` and 0393 rejects negative deltas. A reversal can therefore change current eligibility and refund due without a compensating £250 fee journal. This run exposes `FEE_COMPENSATION_REQUIRED`. A real approved compensating derivation/journal writer is still required before £32 net posted and zero differences can be reached. The fresh two builder-opened withheld-payment case journey and its authorised source adapter must also feed this chain; existing local integration fixtures exercise the accepted catch attribution chain, not that journey. £288 means £320 eligible net less £32 posted, before VAT and tax; it is not subscription money.

No production activation, policy approval, real data or external money action is enabled.
