# MON1-S normal-company source foundation v1

Issued 23 October 2026 under decision 74. Build only; not reviewed, accepted or merged. Synthetic data only. Migration 0209 follows 0208; 0184 fixture APIs remain separate and unchanged.

`MeterLifecycleRepository.capture(context, digest, {version:'meter-lifecycle-capture.v1',commandId,periodStart,expectedSourceRevision})`, `.rebuild(context,digest,{version:'meter-lifecycle-rebuild.v1',sourceId})` and `.read(context,digest,{version:'meter-lifecycle-read.v1',computationId})` accept strict versioned inputs. No count, tenant selector, job list, timestamp, price, small/trial flag or policy is accepted. Missing sources/terms are unavailable, never zero. Capture/rebuild are owner-only; read permits current owner/admin. Every invocation checks current normal-company synthetic session/SSO authority, locks tenant domain 184, then checks authority again before replay/lookup. The shared practice tenant is always refused; no practice/session schema or authority is introduced.

Capture reads accepted monthly agreement, original activation and terms, activation-frozen CH-3a party binding, CH-4 work facts/lock and MON1-T latest trip observation. Original UTC microseconds are formatted by SQL, never round-tripped through JavaScript Date. Work facts include their IDs/sequence/source receipt/command/predecessor and original effective/recorded times. Activation identity, terms and party bindings have job-qualified references; each immutable job input has its own SHA-256 and durable source reference. No shadow table, finding, provider, commercial ledger or fixture loader is consulted.

The snapshot envelope is `meter-lifecycle-source.v1` with provenance `actual_normal_company.v1`; PostgreSQL SHA-256 hashes `jsonb::text` UTF-8 bytes. Computations uniquely bind one source and the `specified-foundation.v1` recipe. Repository reads invoke both MON1-L `projectMeterJobTimeline` and `projectMeterDays` and compare timelines exactly. `resultHash` hashes `JSON.stringify` of that deterministic result; it is a different byte contract from the PostgreSQL source hash. Read/rebuild never refresh source facts. Capture command replay returns the original snapshot; changed period/expected revision conflicts. A new command requires the latest period source revision, starting at zero. Everything rolls back on refusal or projection validation failure.

MON1-L currently returns only held candidates: raw, free-small and counted places are null and there are no intervals or monetary results. This foundation therefore persists a computation recipe and held day cache, not an invented priced result. Read compares cache date cardinality/range/hash/status against the immutable source, emits one durable mismatch alert and computes from the source regardless. The immutable snapshot is never replaced by cache repair. New snapshots retain earlier source/binding bytes. Place-binding and correction storage are reserved: meter has no write grants and the checked entrypoints never write them. The migration owner retains ownership privileges. No fee, negative correction, refund or carry-forward is enabled. Exact late-source correction, previous-correction chaining, closed-receiver checks and chargeable-place attribution remain held pending accepted clock/price integration. They are not claimed complete by the correction-hold tests.

Mid-period plan changes are explicitly unavailable in this foundation because MON1-L accepts one plan for the entire range. The accepted monthly anchor defines the period end, clamped to the next month's length. No trial entitlement or annual plan is inferred.

`jobguard_meter` is NOLOGIN/NOINHERIT/NOBYPASSRLS with no inherited roles, broad schema grants or business UPDATE privileges. Bootstrap also rejects holders except PostgreSQL 16’s ADMIN-only creator membership (no INHERIT or SET). New tables remain migration-owned with enabled/FORCE RLS and tenant-qualified child keys. Runtime has no direct table privileges; its only new callable entrypoints are the three checked lifecycle functions. All four lifecycle functions are owned by `jobguard_meter_owner` after administrative bootstrap, use SECURITY DEFINER and pin `search_path=pg_catalog`. This dedicated owner has the same restricted role posture checks, only the eleven enumerated source SELECT grants with tenant-scoped SELECT policies, six lifecycle SELECT/INSERT grants, and EXECUTE on the existing private `mon1_company_actor` identity bridge. It has no shadow relation/sequence/dedicated-schema privileges or role memberships. The shared app schema requires USAGE; relation privileges remain separate. The pre-existing identity bridge retains its reviewed privileged identity trust boundary and returns only a checked actor.

0209 creates the routines as SECURITY INVOKER so runtime fails closed until the bootstrap admin atomically assigns their narrow owner and enables SECURITY DEFINER. Ownership is never transferred by numbered SQL as jobguard_migration. Temporary transfer permissions are removed/restored before commit. Fresh installs, 0208 upgrades and second-database migrations require this administrative finalization; reruns are supported. Catalogue checks inspect all lifecycle routines, all shadow relations/sequences and dedicated schemas, including column grants. Negative controls reproduce the old migration-owner principal and inject schema/sequence/column privileges in rolled-back transactions. PostgreSQL execution remains CI-only.

## Integration holds

- H-PRACTICE: no session-scoped implementation; the normal-company API rejects shared practice.
- H-TRIAL / MON-3C: trial facts unavailable; no fixture flag fallback.
- H-METER-CLOCK, H-CH4 and H-CORRECTIONS: held candidates only. No monetary correction or closed-site regrouping is enabled.
- Coordinator owns subscription bridge, source hooks and shared catalogue expectations. 0209 adds SELECT grants and separate tenant SELECT policies only for the dedicated routine owner on eleven source tables; existing grants and policies remain intact. Transitive privilege and hidden/no-hidden equivalence review remain required before integration. Source-kernel tests require no test-only meter grants.
- Coordinator must serialize all source writers and plan changes under lock 184 before enabling capture. This source foundation reads job facts in one MVCC statement and takes no business row locks. It cannot prove existing writers already obey the new common serialization protocol. No meter UPDATE grant is needed.
- MON1-L's lifecycle module is appended to the core barrel after the existing exports, before any downstream MON1-S barrel registration. MON1-S consumes it through `@jobguard/core`, whose types resolve to source before a build. No app imports MON1-S's DB modules, so no DB barrel row is needed in this catch-up. MON1-T's `readSmallTrip` is consumed by an internal transaction verification helper; public capture snapshots trips in checked SQL. That helper awaits the coordinator's narrow authorized transaction wiring.
- Actual switch-live/evidence/variation/final-lock end-to-end source journeys, transitive catalogue proof, audit/receipt composition with existing command sources and hidden/no-hidden query equivalence are integration/review holds, not established by fixture-backed tests.

CI must execute the four PostgreSQL files and preserved 0184/subscription regressions. No local PostgreSQL execution is claimed.

Migration `0239_meter_lifecycle_source.sql` applies after MON1-T `0208_meter_small_trip.sql` on fresh install and predecessor upgrade; 0207 is reserved for CH-7-REST-C.
