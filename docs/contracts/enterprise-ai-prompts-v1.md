# ENT-8B fixture possible-extra proposals

This is an internal `packages/ai` fixture evaluator. It runs fixed bundled fictional evidence through M0-12's `AiGateway` and `FixtureAiProvider`. It has no public route, arbitrary text/upload input, database handle, live-provider seam or commercial callback. No provider SDK, network configuration or personal data is introduced.

`enterprise-ai-fixture-request.v1` accepts only a fixture ID, the fixed fixture provider/data class and the server-selected environment. It rejects extra fields. Only `synthetic_demo` is enabled. `enterprise_ai_prompts` refuses `pilot_no_charge` and `production_billing` before provider execution. Approval booleans cannot open a route. M0-12a, D04, the DPA, G2 and live-model evaluation remain prerequisites for future real use. The mode field here is an internal calculation constraint, never session or tenant authority.

`enterprise-ai-output.v1` contains descriptions, `clear|review` ambiguity labels and exact citations. Every nesting level is strict. It cannot carry origin, price, approval, fee status, tenant/job identity, scope identity or coalescing identity. Notes, transcripts and photo captions are source data; the fixed operation/prompt/schema remain separate. One optional local repair callback runs at most once through the merged gateway; the repaired output is subject to the same schema and citation checks.

The bundled baseline revision and ordered work are passed to the gateway with their hash. Each cited source must belong to the fixed tenant/job and be verified and uninvalidated in the fictional stored snapshot. UTF-8 SHA-256, immutable object-version identity, UTF-16 span bounds, exact quoted slice and gateway citation-envelope coverage must all agree. Baseline text cannot be used as evidence. These checks verify bundled snapshots, not PostgreSQL finalization, uploaded bytes or the factual truth of work performed. Provenance retains model/deployment, prompt/schema, fixture, source hashes and evaluation version.

Results remain advisory candidates. No scope item, variation, origin, price, approval or fee is written. The merged ENT-8a contract explicitly holds prompt persistence, coalescing, confirmation and dismissal; `ConfirmPrompt` also remains refused by merged database authority checks. This piece therefore keeps its output distinct from `enterprisePromptProposalV1`, whose required coalescing key needs that held policy. It does not invent a substitute writer or expand who can act. Integration with the Possible extras lane and exactly-one-extra confirmation is BLOCKED on those prerequisites.

No migrations, grants, backfills, external actions, new operational alerts, environment variables or provider/data-flow register changes are required. Existing public contracts and merged tests stay unchanged. SoR suggestions belong to ENT-8B-SOR; UI remains parked. This is source-built fixture behaviour, awaiting an independent exact-commit verdict and separate acceptance.
