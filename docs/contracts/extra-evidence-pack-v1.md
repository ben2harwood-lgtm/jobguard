# Extra evidence source adapter v1 — partial foundation

Q09 dispatcher ruling, 13 October 2026: use `app.extra_evidence_pack`, subject `extra`, and a versioned adapter to the merged integrity verifier. No recovery case is invented or inserted. No predecessor table gains a column. The adapter maps a subject-qualified extra identity to the verifier's legacy `caseId` slot solely inside its internal manifest; this is an integrity key, not a recovery-case relationship. Public extra artifacts retain an explicit extra subject envelope.

Read-only source loading uses tenant/job/extra-qualified persisted origin, exact verified photo object/version/hash, the labelled ENT-3d capture confirmation, and unchanged ENT-3c SoR revision/basis. Named-column JSON text avoids driver timestamp rounding and predecessor whole-row dependencies. Loading takes a database snapshot first; assembly reads original photo bytes from the exact private versioned storage adapter after the transaction commits and checks server-verified hash/length. No network call occurs inside the source transaction. The ENT-3d confirmation document is deterministically reconstructed from its registered content/version and must match its server-verified hash and byte length. Required missing, pending, rejected, invalidated or wrong-subject evidence refuses loading. Optional absence is explicit. Confirmation verifies capture content only and is labelled **confirmed on the operative's device; identity not verified**; quantity and price are outside that capture hash.

Shared `inspectEvidenceManifest` and `verifyStandalonePack` supply integrity findings. Trusted checkpoint evidence is separate from content integrity and from the truth of photographed work. A wrapper subject must match its inner manifest. Loading again checks the current persisted source identities and hashes; a self-consistent edited export cannot substitute for those sources.

HELD: complete requirement, approval-step and work-timing sources, actor-bound pack revision creation, client access and export/send. Every foundation artifact explicitly omits those sources and cannot claim a complete approval pack. Only the immutable subject container is persisted by this migration; there is no runtime pack writer. Existing recovery artifacts and verifier contracts are unchanged. Forward fix: later reviewed migration, never deleting history. Old code ignores new tables; no new endpoints exist. The read-only repository returns a typed migration-required failure if its container schema is absent.
