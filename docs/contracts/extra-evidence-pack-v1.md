# Extra evidence source adapter v1 — partial foundation

Q09 dispatcher ruling, 13 October 2026: use `app.extra_evidence_pack`, subject `extra`, and a versioned adapter to the merged integrity verifier. No recovery case is invented or inserted. No predecessor table gains a column. The adapter maps a subject-qualified extra identity to the verifier's legacy `caseId` slot solely inside its internal manifest; this is an integrity key, not a recovery-case relationship. Public extra artifacts retain an explicit extra subject envelope.

Read-only source loading uses tenant/job/extra-qualified persisted origin, exact verified photo object/version/hash, the labelled ENT-3d capture confirmation, and unchanged ENT-3c SoR revision/basis. Named-column JSON text avoids driver timestamp rounding and predecessor whole-row dependencies. Loading takes a database snapshot first; assembly reads original photo bytes from the exact private versioned storage adapter after the transaction commits and checks server-verified hash/length. No network call occurs inside the source transaction. The ENT-3d confirmation document is deterministically reconstructed from its registered content/version and must match its server-verified hash and byte length. Required missing, pending, rejected, invalidated or wrong-subject evidence refuses loading. Optional absence is explicit. Confirmation verifies capture content only and is labelled **confirmed on the operative's device; identity not verified**; quantity and price are outside that capture hash.

Shared `inspectEvidenceManifest` and `verifyStandalonePack` supply integrity findings. Trusted checkpoint evidence is separate from content integrity and from the truth of photographed work. A wrapper subject must match its inner manifest. Loading again checks the current persisted source identities and hashes; a self-consistent edited export cannot substitute for those sources.

Requirement/step source slice (ENT-5, RED): the read-only adapter now selects the latest request once, with its frozen `extra-approval-requirement.v1` snapshot, rule/contract versions, pricing binding ID, exact revision hash/net, comparisons and request hash. That request is a versioned `extra_approval_request:<id>` approval source (version = request revision). Its tenant/job/extra/request-qualified step facts and optional outcome are separate version-1 sources. Request, steps and outcome are read in one SQL MVCC snapshot; dependent facts never reselect the latest request. The immutable step index, role, actor kind, membership reference, approved hash/net and server time remain inspectable. A client step keeps `actor_kind=client_approver`; it is never relabelled a contractor attestation. No client-link table, token, email, resident contact, fictional role free text or tester reference is included.

An absent request is labelled explicitly. Pending, rejected, withdrawn or duplicate outcomes and missing/mismatched required steps carry an approval-not-complete omission. An approved outcome alone cannot establish completeness: every indexed requirement must match the corresponding fact's role, actor kind, hash and net. An old pack remains the snapshot it was; a later approval or revision cannot fill its omissions or replace its request identity. Source array order is immaterial to the shared verifier; editing the recorded step indices or requirement order changes hashed content. A self-consistent edited export still requires comparison against persisted sources or an independently trusted manifest digest; an export cannot attest to its own authenticity.

HELD: work-timing sources (`Extra work timing HELD`), actor-bound pack revision creation, client access and export/send. Every new artifact explicitly omits timing and cannot claim a complete approval pack. Earlier `extra-source-pack.v1` artifacts retaining `Approval requirement, steps and extra work timing HELD` remain readable and verifiable with that original, honest omission. The wrapper version and shared verifier are unchanged. Timing, proceed, T/Y composition and reporting-authority policy remain open; this slice does not close ENT-5. Only the immutable subject container was added by the foundation migration; there is no runtime pack writer. Existing recovery artifacts and verifier contracts are unchanged. Forward fix: later reviewed migration, never deleting history. Old code ignores new tables; no new endpoints exist. The read-only repository returns a typed migration-required failure if its container schema is absent.
