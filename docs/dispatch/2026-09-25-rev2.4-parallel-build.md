| Role | Who | Does |

| Founder | **Ben** | Owns decisions, live work, spending, deploys and releases; can stop the loop at any time |

A builder never accepts its own work. For PRs Claude authors (plan and dispatch changes), Codex's review is the independent check and Ben merges.

**How a local build runs:** `codex exec --worktree -s workspace-write --approve-for-me -o <receipt> "<work order>"` from the repo root, one process per ready task, up to five at once. Sessions run on the desktop app's shared local agent service, so Ben can watch them in the Codex app. GitHub CI runs the full suite (PostgreSQL, MinIO, browser tests) on every PR; local runs cover what the Mac can run. Until Docker Desktop is installed, Codex runs typecheck, lint, unit tests and build locally and CI runs the database and browser suites.

**Merge authority:** the checker merges only when CI is fully green, its recorded verdict is ACCEPT, and the PR touches no founder-reserved area (live providers, production mode, real data, spending, decision approvals, deploys). This follows the founder's cloud-autonomous direction in `JOBGUARD_BUILD_PACK.md` §0. Anything else waits for Ben.

## 4. Keeping parallel tasks from colliding

1. **Migration numbers are pre-allocated** in the table. A task uses only its number. The checker merges in migration order within ready PRs; if a lower-numbered PR is stuck for more than a day, the checker renumbers the waiting one in a fix request.
2. **One lane per task.** The work order gives the branch prefix; the task's first commit adds its lane to `config/agent-lane-assignments.json` using `branchPrefixes: ["codex/jg-<id>"]`, its e2e spec path and its allowed scopes. No blanket grants.
3. **Shared registration files** (`apps/api/src/app.module.ts`, `apps/api/openapi.json`, `packages/core/src/index.ts`, `packages/db/src/index.ts`, web navigation, the lane registry) may be touched by every task, append-only. After each merge the checker asks any now-conflicting open PR to rebase on `main` and regenerate OpenAPI.
4. **Declared overlaps serialize.** CH-1 and SV-6 both touch the fee illustration; SV-6 waits for CH-1 anyway through the graph. CH-2 and CH-4 touch the same repositories; CH-4 waits for CH-2. If Codex finds an undeclared overlap it says so in the receipt.
5. **Always branch from the latest `main`.**

## 6. The checker loop (each tick)

1. **Finished Codex runs:** push the branch, open the PR with the receipt as its description, and wait for CI. Read the diff, the receipt and Codex's automatic review. Check the task's "Done when" against the code and the CI results. Record `docs/verdicts/<TASK>/<commit>.md` with ACCEPT or REVISE, stating what was source-inspected, what was test-executed and what was not verified.
2. **REVISE:** resume that task's Codex session (`codex exec resume <session>`) with one message listing exact required fixes, then push the new commits. **ACCEPT and CI green:** merge (squash) in migration order, then ask conflicting siblings to rebase.
3. **Dispatch:** for every task whose dependencies are now merged and which has no running session or open PR, start `codex exec` with the work order, up to five running at once.
4. **Stalls:** a Codex run that exits without a receipt or with failing local checks is resumed once with the failure; if it fails again, mark it blocked on the tracker and move on. A PR stuck in review more than two rounds → flag for Ben.
5. **Tracker:** update the rev 2.4 tracker issue (queued / running / ready for review / accepted / merged / blocked, with timestamps and links). Never mark something accepted without a recorded verdict.
6. **Stop and ask Ben** for: any founder-reserved area, a failing CI check that needs weakening to pass, a conflict between the plan and the code that changes a contract, or a decision record that would need approval.
