# Connector reconciliation requirements — implementation held

No connector executor, delivery history, queue, scheduler, reconciliation command or operational control is implemented by ENT-13A's issued portion. These are requirements for later release, not an executable runbook. Existing ENT-6 adapters are process-local simulations; their state does not survive restart and is not payment/delivery evidence.

An outbound transfer must bind the immutable already authorised ENT-6 artifact, its exact hash/bytes, client contract, endpoint version, owning outbox action and stable effect identity. A durable attempt must commit before the adapter call; no business network call occurs inside a transaction. Current authority and artifact bindings must be rechecked before execution. Only the owning outbox scheduler may dispatch; this leaf introduces no second polling or orchestration owner.

If a server may have accepted an artifact and its reply is lost, record `outcome_unknown` against the original attempt. Restart, redelivery or a changed filename must not trigger a blind resend. Reconciliation must establish original success, safe absence or continuing uncertainty, preserving the original effect identity and evidence. A retry requires established safe non-delivery and current authority under the adopted policy. Disconnect must stop future claims while preserving attempted-transfer history and a permitted path to reconcile it; the authority for that path is held under Q2/Q3/Q6.

Inbound source event identity is independent of transport, request ID, filename or credential version. Same identity and canonical payload must have one effect; changed payload must conflict without replacing the first result. A payment received by file and API needs ENT-6's explicit reconciliation identity or durable ambiguity hold. Complete ordinary invoice lines remain in allocations and contribute zero fee. Reordered facts follow ENT-6's adopted policy; connectors cannot infer settlement, manufacture missing composition or resolve causal ambiguity by arrival order.

Late billing facts, credits, reversals and delivery reconciliation must follow an explicitly adopted ENT-6 lifecycle. Neither a blanket live-only rule nor a post-live exception is chosen here (Q6). Materials and work-order operations retain their own owning lifecycle requirements, subject to Q7 and the missing ENT-8a integration.

Before activation, provide checked routines, durable persistence/restart proofs, revocation and concurrency tests, fault-capable external fake-server execution, safe diagnostics and assigned incident ownership. Required alerts cover ageing unknown outcomes, conflicts, quarantine and failed reconciliation; thresholds remain unset. Support access requires separately authorised, audited emergency access. Never edit immutable receipts, payment facts, origins or artifacts to make an uncertain result appear successful. No manual settlement override is authorised.

E13-A19–A23 and related application/HTTP proofs remain held. Real endpoints need G5 and the completed [data-flow register](connector-data-flow.md); this document supplies neither release nor security approval.
