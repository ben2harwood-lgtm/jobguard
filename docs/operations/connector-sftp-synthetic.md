# ENT-13a slice 2: dark SFTP transport seam

`apps/api/src/connectors/sftp.synthetic.ts` implements an in-memory fake file server and pull/push client seam. It opens no sockets and reads no files or secrets. No SFTP library is installed in the pinned workspace; none was added. This is deterministic fake-server coverage, not an SFTP protocol or external-server integration test.

The harness supplies the existing strict `connector-environment.v1` configuration: only `synthetic_demo`, `fake` and `fixture:` endpoint/credential labels are accepted. A strict `sftp-fixture-scope.v1` selects tenant, client contract, operations and an explicit fixture byte limit (at most the existing 5 MB parser limit). These are test parameters, not an adopted machine capability or production size/security policy. Real endpoint configuration is refused; there is no route, worker registration, scheduler or activation switch.

Pull accepts only versioned `sftp-fixture-file.v1` envelopes with fictional file/source/event labels. Tenant, contract and operation are checked before returning domain data. Work orders reuse `workOrderRowV1`, billing reuses `parseBillingImportEnvelope`, and materials reuse `materialsIssueV1`. Outputs are parsed proposals only. Materials returns/corrections and reordered observations remain proposals for the owning domain to reconcile. No connector command can approve, price, write origin, access statements or inspect shadow data. No database or domain writer is connected.

Identical source/event proposals replay across filenames and credential-label rotation; changed validated payloads conflict. Billing comparison uses canonical observations independently of raw source-byte hashes. This process-local observation map is not durable idempotency or proof of cross-channel business deduplication. The owning domain remains responsible for its stable source identities and atomic command/receipt/audit.

Push implements the existing `OutboundAdapter` seam for `fake_sftp` and only immutable billing exports. It reuses billing artifact/hash/amount validation and checks the artifact contract and its tenant against a harness-owned contract-to-tenant map copied when the fake server is created. Missing ownership fails closed. The UTF-8 byte limit is checked before artifact parsing or hashing. It simulates success, acceptance with lost reply, established absence and unresolved interruption. Same-effect replays do not create another simulated effect; changed bindings conflict. Reconnecting clients see the fake server's original observation. Reconciliation never resends. Unknown server/effect state returns `unknown`, including after replacing the fake server. Established absence does not itself retry. This is not durable delivery evidence or exactly-once network delivery.

A future caller must obtain tenant/contract scope from verified server authority, and use the existing owning outbox's current approval, expiry, lifecycle, claim, attempt and audit checks. This seam grants none of those permissions. Export v1 has no tenant field; the fixture ownership map stands in for that lookup and must never be populated from client-supplied scope. No production credential, authentication, host-key/path/redirect policy, rotation overlap or post-revocation authority is invented.

No migration, grant, environment variable, dependency or UI change. Remaining work: adopted machine capability/authentication and credential custody, real SFTP library and external fake-server toolchain, durable import/outbox composition and restart proofs, domain allocation/locked-bill/lifecycle enforcement, operational monitoring and G5 endpoint/data-flow approval. The existing connector requirements and reconciliation holds still apply; this seam does not complete ENT-13a or release real endpoints.
