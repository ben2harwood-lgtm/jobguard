# D4B privacy note: translated crew briefs (draft for Ben, 25 Nov 2026)

**What would leave JobGuard.** Only the brief's working text goes to the translation service:
- the trade;
- the access window;
- task titles;
- scope wording;
- visit notes;
- the proof needed.

These never go:
- the person's name (`owner`);
- quantities, prices or ids;
- photos;
- the customer's name or address, which the brief doesn't hold.

The builder's free-typed scope wording might still mention a name or address. So before the real provider goes live, the builder sees exactly what will be sent and can edit it.

**Before any real use (after the practice piece):**
1. **Ben picks a service.** Common choices are DeepL API, Google Cloud Translation and Microsoft Azure Translator. Each charges per character, with a free tier at some providers; check current prices. Choose a plan that does **not** keep or train on submitted text, and that can process in the UK or EU.
2. **A data-processing agreement** with that provider, and the provider listed in JobGuard's privacy notice as a processor.
3. **A monthly spend cap** set in the provider account, plus a per-firm character cap in JobGuard.
4. **The firm switches it on**, per firm. It's off by default.
5. A RED plan check of the real-adapter packet (Astra).

**Practice now.** The practice piece (Q41) uses a fake, offline translator. Nothing is sent anywhere, and nothing costs money.
