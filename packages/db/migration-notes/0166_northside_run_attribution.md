Adds two tenant business tables with forced RLS, tenant-qualified business FKs, SELECT-only runtime grants and immutable history guards. Session/switch FKs refer to existing private control-plane exceptions: the trigger verifies their tenant, owner, persisted identity and current switch, rather than granting the runtime control-plane access. `northside_register` is the only new runtime-callable function. It requires the active persisted practice owner, a made-up company, no open switch, and synthetic database. Settings hash is SHA-256 of PostgreSQL's stored JSONB text encoded as UTF-8. It is an immutable database snapshot hash, not a model/schema fingerprint.

Six additive AFTER INSERT triggers attach source references for command receipts, imports, uploads, evidence objects, rate versions and contract versions. They do nothing without a Northside run. They bind source insertion to the run's persisted owner session and current fictional actor, refuse mismatched receipt/import/rate actors, and keep original command audits and origin records unchanged. Attribution rolls back with its source. Receipt attribution exists while processing inside the transaction; a successful command keeps that same immutable attribution. Upload/evidence attribution describes the stored lifecycle fact, not delivery or successful extra approval. Replays do not rewrite attribution. No advisory lock is introduced in the source triggers; all FK/source work happens before existing final audit appends. Registration locks tenant key 54, then the existing switch session key 16501, before mutation and audit.

No predecessor row is backfilled or updated. Existing runs made before this change are not silently claimed as verified test runs. Creating a new run gives the full seed/settings/attribution evidence. Start/revoke and switch commands keep their existing owner-audited records; the new run references that original session. The actual tester is the persisted practice owner identity; this is not proof of a named person's external identity or protection against a compromised privileged login.
