# LATER-B14 — durable Decision check responses

Migration 0193 is additive: one checked execution routine and two receipt guard functions/triggers. It reuses `command_receipt`, `decision`, `job_finding`, `finding_suppression` and `audit_event`; no table or column is added and no existing row is changed. The migration runner discovers it without a registry edit.

The sole new grant is EXECUTE on `app.decision_check_command(text,jsonb,text,jsonb)` to `jobguard_runtime`. Standard F: no new direct runtime INSERT, UPDATE or DELETE grant. The SECURITY DEFINER owner is `jobguard_migration`; each phase checks the persisted synthetic session, active owner membership, tenant and inherited job ownership before taking the job/command locks or returning replay. Existing builder practice checks remain available before live; this endpoint accepts only the fixed synthetic builder tenant, not contractor principals. There is no new route, classification rule or authorization policy.

The request hash covers the versioned command including job and check ID. Receipt uniqueness serializes concurrent check IDs; a repeat returns the first complete response, and reuse for another job/type/payload conflicts. Strict input rejects added fields. All findings, completed receipt and identifier-only audit append commit together. A deferred constraint rejects an incomplete phase sequence; completed responses cannot be rewritten. The audit head is the final new lock. Check identity is in the receipt namespace; this migration does not extend the separate watchdog command registry or its replay harness.

Current projections omit retired/ineligible scope and proof satisfied by current verified original evidence on the same tenant/job/scope/type and object version, excluding invalidations. Stored finding content/classification changes receive distinct deterministic fingerprints; current subject projections select their latest revision before suppression/resolution is applied. Historical rows and old command responses remain intact. Missing current proof keeps its mandatory requirement open; an old proof resolution is retained as history, not treated as proof.

The synthetic rule recipe (first eligible scope electrical, second scope materials, existing 20,000-pence suggestion values) is retained. This work does not introduce a persisted general-purpose rule configuration or perform a new storage-byte verification during a projection. Persisted finalized evidence is the input to this check, not a new claim that bytes were inspected by these tests.
